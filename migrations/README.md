# PostgreSQL migrations (server mode)

При создании нового PostgreSQL volume Docker Compose монтирует только `schema_pg.sql` в `/docker-entrypoint-initdb.d/`; он создаёт bootstrap-схему и `schema_migrations`. Файлы из `migrations/*.sql` применяет Python runner `app/db_pg.py` при старте приложения в лексикографическом порядке.

Для каждой применённой миграции runner хранит SHA-256 и останавливает запуск при изменении её файла. Не редактируйте применённые SQL-файлы: исправления оформляйте новой миграцией.

## Новая миграция

1. Добавьте `00N_short_name.sql` с очередным номером.
2. По возможности делайте изменения добавочными и повторяемыми.
3. Проверьте миграцию на копии базы и добавьте тесты.

Перед применением на рабочей базе нужны согласованный бэкап PostgreSQL и `max_server_data`, проверка восстановления и recovery hold. Порядок описан в `docs/PRODUCTION-OPS.md` и `docs/audit/migrations.md`. Автоматических down-миграций нет; откат выполняется вручную SQL или восстановлением согласованного бэкапа.
